# Caveman × TTA Tone 场景对照

基线是“不加载 TTA Tone”的常见默认回答；TTA 版本应用当前 `skills/tta-tone/SKILL.md`，先做场景路由，再选择 Normal/Tight/Compressed 密度。示例用于行为回归，不是 provider token 或质量实测。

## 1. 普通技术解释（Direct / Casual，Tight）

**输入**：解释为什么 Python 的列表推导式比手写循环更简洁。控制在两句。

**默认回答**：列表推导式是一种非常方便且强大的 Python 特性，它允许你用更加简洁、优雅和可读的方式，根据已有的可迭代对象创建一个新的列表。相比之下，手写循环通常需要更多的代码行，因此列表推导式在很多情况下会更高效。

**TTA Tone**：列表推导式把遍历、条件和结果放在一行；手写循环通常要分成多行。它主要减少的是表达长度，不自动代表运行更快。

**差异**：去掉宣传式形容词；保留“更短”与“运行速度不等价”的边界，避免把简洁误说成性能结论。

## 2. 不可逆操作与未确认备份（Agent Output，Auto-Clarity）

**输入**：给我一条执行汇报：准备运行 `DROP TABLE users;`，但备份状态还没确认。

**默认回答**：准备执行数据库清理操作。下一步会删除 `users` 表，执行前请确认备份已经完成。

**TTA Tone**：备份状态尚未确认，暂不能安全执行 `DROP TABLE users;`。该命令会永久删除 `users` 表且无法撤销；先确认可恢复备份，再执行并重新验证。

**差异**：压缩在风险点自动停用，保留不可逆后果、前置条件和顺序；不把“准备执行”写成已经执行。

## 3. 错误报告与候选原因（Agent Output，Tight）

**输入**：报告错误：deploy.log:18 出现 `timeout`，目前不知道是网络还是服务启动慢。

**默认回答**：部署过程中出现了超时问题，可能是网络连接不稳定，也可能是服务启动较慢导致的。建议检查网络状况和服务日志，以便进一步定位和解决问题。

**TTA Tone**：`deploy.log:18` 出现 `timeout`。原因尚未确认：候选是网络问题或服务启动慢；先对照同一时间段的网络记录和启动日志。

**差异**：保留原始字面量；把两个原因明确标为候选，并给出能区分它们的证据，不制造确定结论。

## 4. 保留结构、命令和范围（Preservation Edit，Normal）

**输入**：去 AI 味但保持结构和字面量：
## 结果
`npm test -- auth.spec.ts` 已通过，耗时 42 秒。

## 限制
只在 Windows 本机跑过。

**默认回答**：## 测试结果
测试命令 `npm test -- auth.spec.ts` 已成功执行，整体表现良好。

## 注意事项
目前只在 Windows 环境进行了验证，后续还需要在其他环境中进行测试。

**TTA Tone**：## 结果
`npm test -- auth.spec.ts` 已通过，耗时 42 秒。

## 限制
只在 Windows 本机跑过。

**差异**：默认回答改了标题、删掉了耗时并扩展了未要求的后续；Preservation Edit 锁住结构、命令、数值和验证范围，只做必要的措辞变化。

## 5. 部分完成与运行验证边界（Agent Output，Tight + Auto-Clarity）

**输入**：汇报当前状态：代码已写入，静态检查通过，浏览器验收未完成；不要把未完成说成完成。

**默认回答**：相关功能已经完成，代码已成功写入，静态检查也顺利通过。目前整体状态良好，后续可以继续进行浏览器验收。

**TTA Tone**：代码已写入，静态检查通过；浏览器验收尚未完成。因此当前是“已集成、已静态验证”，还不能称为运行验收完成。

**差异**：把不同验证层级分开，保留未完成状态；压缩掉仪式性语句，但不压缩成会掩盖风险的“已完成”。

## 观察结论

五个场景里，TTA Tone 的变化来自三条可检查规则：先路由，再选密度；技术字面量和证据不压缩；遇到风险、不可逆动作或不确定性时恢复完整表达。Caveman 的 proxy、middleware、hook 和 token 节省数字没有混入语言层；它们需要独立运行时与同任务 A/B，不能由这五个文本例子证明。
