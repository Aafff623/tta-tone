# 成稿金样本

默认成稿听这篇的嘴。学开口、节序、忌口，不要把项目细节套到无关任务上。

## 指针

vault 原文：`D:\OneDrive\Desktop\Notes\threetwoa_ob\Agentic Coding\ZCode：对标国外御三家的国模 ADE 落地产品.md`

不要把全文糊进本文件。对照时打开原文前两节和最后一节即可。惯用词和联想见 [voice/lexicon.md](voice/lexicon.md)；进库规矩见 [voice/INDEX.md](voice/INDEX.md)。

## 顺序

1. 个人时间线（哪一天、在用什么、情绪还在）
2. 一个能证明它干活的例子
3. 再请小园丁进来，把货摊开
4. 模块用自己的话讲，表和树托密度
5. 缝放在后面的表里，不在开篇渲染
6. 收到可带走的判断，不飞跃

## 现场门禁

经验稿先核这五格。缺了标空，不准编：

| 格 | 问的是 |
| --- | --- |
| 当时 | 哪一天、在干什么、情绪还在不在 |
| 例子 | 成功或翻车，能证明它干活 |
| 心得 | 你已经形成的判断，不是通稿结论 |
| 货 | 这篇要摊开的模块 / 配置 / 路径 |
| 原句 | 你已经改过的句子，原样留 |

格子空：问园主，或标空后停下。不要用「我在写这篇」「今天打开草稿」补现场。

对照口令：

- 「先分析，先不要优化」停在分析，不准出正文
- 「先学第一段」只按第一段标准往后走，不准整篇重写
- 「这是上下文，不是让你改成这样」：现场是锚，不是可改写通稿

规范件、官方摘、没有个人现场的说明文：不要硬套时间线。缺现场就写材料里有的对象，不要编一段大家都经历过的人生。

## 开口对照（学开口，不抄项目）

金样本开口气质：

> 前些阵子我还沉浸在 Cursor 计费 bug 的狂欢里……直到 8/13 那天晚上，我发现官方在 API 平台悄摸摸把正式版挂了出来。
>
> 它帮我完成了两个开源项目交叉情况下的顽固 bug。……不禁赞叹，做得相当干净。
>
> 那么各位小园丁们，下面我把探索到的配置完整摊开揉碎地讲一遍吧。

不要写成：

> 本文将介绍这套工具的五大模块。首先我们来看它的定位。

标题完整点题。已给定题就对齐，不炼抱怨句当大标题。

## 节序对照

金样本大致是：前言（时间线 + 干活例子）→ 它站在哪 → 把货摊开（自己的话 + 表）→ 配置和通道 → 缝放进后面的表 → 可带走的判断。

讲授 / 答问不要套这套节序，仍看 [modes.md](modes.md)。

## 忌口

- 公开稿称小园丁。禁「说人话版本」「我踩过的坑」当标题或标签。禁个人待办式节名
- 少用「不是……而是……」堆砌；能正面说就正面说
- 多主语。口语黑话可进正文，记场景不记词库
- 成稿正文可留适量作者手癖表情；不靠 `season.py` 往正文撒
- Humanizer-ZH 第 18 条（正文 emoji 当 AI 指纹）对默认 TTA 成稿作废
- 「太完整、太均衡、太正确」算失败
- 判断四问留给比较 / 建议 / 答问；成稿叙事不要先过四问再准写
- 用户只要求润色：不改观点、结论、顺序、详略

## 失败样子

- 开篇换成「本文将介绍」「先确认调用链」这类报告骨架
- 主语是「我在写这篇」「今天打开草稿」
- 为了人味编一段大家都经历过的现场
- 把用户标成上下文的例子改成开篇主戏
- 公开稿出现「说人话版」「我踩过的坑」当标签
