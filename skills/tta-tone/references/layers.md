# 招式检测和交付

用户只点名分支和语气。轻 / 述 / 拆**不是**第三根要填的轴，不要口头报层号。

默认按 [modes.md](modes.md) 的骨架写。线索命中再抽招式。写完再看要不要交接姐妹 Skill。思考深度和媒介不要绑死：深度论证可以全程 Markdown；点名要分享页时，思考仍可以很短。

---

## 什么时候动手，什么时候收着

| 这轮实际是 | 怎么做 |
| --- | --- |
| 闲聊、简单确认、挑样子 | 接住这一则在干什么就回。四问不必走完。混排最多两处，可走 `play` |
| 一般讲解、成稿、一条路已经明显的答问 | 现有骨架。混排一处 |
| 下面「线索」有一条命中 | 只抽命中的招式，不要把八条整套搬出来 |

风险 / FAIL / 密钥 / 标识：只写事实句。零调味。不要用图或动画冲淡。

## 线索 → 招式

命中才用。接到「判断」和「怎么排」，不另开第五问。嘲讽、羞辱、励志收束不接。

| 线索 | 招式 | 做法 |
| --- | --- | --- |
| 在比整份工具、框架、语言的牌子 | 收窄层级 | 先写死这轮争的是牌子还是那一个可复用的能力。能力没拆开时，牌子之争标空 |
| 桌上有对方原话、报错全文、接口约定 | 先引后判 | 整段放进引用框，框内不夹评。判断写在框外。引用不能当第一句 |
| 能预见到会有人反驳 | 预写反驳 | 反对句里先复述对方中心论点，再写这句话要成立的前提，再看这轮材料撑不撑住。不要拿反驳当开篇 |
| 一次方便的做法被说成普遍规律 | 集合 | 一次特例不能定义整类 |
| 两件事一起出现，被写成因果 | 充分必要 | 同时发生不等于有因果 |
| 连续多条需要被证伪的结论 | 可证伪编号 | 每条写清怎样算成立、怎样算不成立。编号只放判断段 |
| 对方问的是做法 Y | X 还是 Y | 先核要解的问题是不是 X |
| 答问，且多条路都走得通、限制不同 | 决策壳 | 各写能力与限制，只推荐一条。凑不出三条不要硬凑。细则在 [modes.md](modes.md) 答问「子场合壳」 |
| 成稿或润色已经写出一稿 | 稿后再审 | 还剩哪些套话壳；有没有多出材料里没有的事实、名字、数字、日期。第二问过不了就改回材料里有的说法 |

开发流程、harness、何时停、写给 agent 的文档：走 [kb/INDEX.md](kb/INDEX.md)，只抽命中的短卡。这不是新招式轴，也不要让用户报编号。闲聊、纯润色不读。

## 写完再交付

tta-tone 不管页面主题、动画时间线和配图语言。默认停在 Markdown。用户点名、或材料明确要那一类成品时，再交接。不要因为内容复杂就自动做 landing page。

| 用户要的成品 | 交给谁 | 不要 |
| --- | --- | --- |
| 对话、文档、对照 | Markdown：标题、列表、引用、表 | 用装饰图代替判断 |
| 模块关系、调用链、可编辑架构 | 文内结构图（如 Mermaid）或可编辑图 | 生图模型画一张「看起来像架构图」的图充数 |
| 单页分享 | `tta-html`（须点名或明确要分享页） | 讲授默认做成页面 |
| 16:9 翻页 | `tta-ppt` | 把讲解默认做成幻灯片 |
| 过程、状态切换、可交互动作 | `tta-motion` | 在本 Skill 里手写一套动画引擎 |
| 漫画解释、角色 | `tta-visual`；点名生图再走本机生图入口 | 专业架构、企业模块、科研机理图当位图交 |
| 封面 | `tta-cover` | 用封面代替正文判断 |

专业架构要可核对、可改，走结构图。生图只解决该是插画的插画。不确定问一句：这张是文内解释图，还是要可编辑的专业图。

交接后文案仍按本 Skill：开篇有主语，不编造，不营销。成稿跟 [canon.md](canon.md)。视觉语言由对方 Skill 定。
