## 研究对照体的纪律

多工具、多方案写成同一张对照表时，语料里已经跑熟的规矩：

1. 文首写核对日和渠道（本机实证 / 官方文档 / 社区帖）。
2. 官方口径、本机实测、社区说法三源分开写；「官方说支持」不当成「本机跑通」。
3. 文档互相打架、文档和本机不一致的条目单独列一节，不拌进正文表。
4. 空单元格写「本机未见 / 文档未写」，不编，不空着不管。
5. 可带走的判断放最后，且只写材料撑得住的那几条。

## 人格稿公共招式

修仙专栏各人格（小烨、林晓丁、玄灵、小沅、玄成先生等）各有一张嘴，但壳是共用的。学招式，不抄设定：

1. **开场定框。** 加粗心法引文，或对读者的设问开场。成稿「开篇有主语」在这类稿里由设问或引文承担，但仍要能回答这话是谁对谁说。
2. **读者框定免责。** 一句把内容定位讲清（当故事也行、当世界观也行、当睡前乐子也可以）。这是人格稿管事实边界的方式，不用「仅供参考」那种客套。
3. **加粗金句承重。** 每节一到两句加粗判断；不要处处加粗，加粗就真承重。
4. **制度隐喻幽默。** 把设定翻译成行政机构、考编、户籍、办事处这类制度词来出效果。幽默有事实对象（设定本身），用完回正题。
5. **直斥插句。** 口语短句直接驳回常见误解。驳的是观点，不是人；不违反「贬低别人抬自己」的忌口。
6. **例块。** 抽象规则后跟两三个具名例块（三类修行人）。例块是设定推演，标明虚构，不当已发生的事。
7. **口播收尾。** 签名加预告（我是 XX，我们下集再见）。仅人格稿；默认成稿不签名。
8. **事实照旧。** 人格稿不豁免事实边界。现实人物、书目、年代照样标来源（语料里玄成先生引维基、写「我校验后认为」就是样子）；设定和现实分开写。

## 喂养流程 v2

喂语料走这七步，不手摇。「没有卡」是合格产出；语气件的嗓音只许来自园主成稿，外部语料的嗓音一律「语气不借」。

0. **语料体检。** 每份语料先定性：正例 / 反例 / 混合，写出学什么、不学什么。反例同样入库，标反面教材。
1. **投喂。** 语料进训练库或 vault，路径记进 [ledger.md](ledger.md)。
2. **提炼。** 产出候选规则卡：类型（词 / 壳 / 忌口 / 版面 / 招式）、规律本身、原文证据句、证据数量、落点文件。证据 ≥2 篇或两个场景才报骨架层；单例只报参照层。
3. **审批。** 分级：碰身份、语气、事实边界的卡必审；纯词表、参照指针类低风险卡批量放行或只落参照层。
4. **固化。** 批准的卡写进落点文件；编号（R-001 起）和来源记入 [../rule-cards.md](../rule-cards.md) 名册。先查重，撞了已有卡就声明冲突而不是另写一条。
5. **回归。** 新规则配新 eval；`evals` 全量 PASS 加 `tone_lint.py --self-test` PASS 才算入库完成。真实交付中被园主改回去的句子，转成 lint 规则或 eval 用例，这是最高优先级的负样本。
6. **修剪。** 定期审计：从未命中或互相重叠的规则合并退役，lint 规则同步瘦身，删卡留编号。

## 候选档规则

这些人格是候选语气档，不是已登记档。在 modes.md 语气表登记之前：

1. 点名人格写稿时，按上表对应文章学壳，按人格自己的称呼、开口和收尾写。
2. 没登记的档不冒充 modes.md 已登记语气，也不现在就往语气表加行。
3. 长训完成、某一格的开口和忌口稳定后，再按 [modes.md](../modes.md)「怎么加一档」登记。

### 机会性点名（voice adoption）

长篇成稿或深度改写时，可以问一次用户要不要套人格档（协议借鉴 ai-zixun/humanizer-zh，条件按本仓实况收窄）：

- 同一会话最多问一次；用户拒绝或忽略，本会话不再提，全部走默认。
- 只在任务真是人格专栏 / 口播稿（修仙系列这类）而用户没点名时问；普通成稿、润色、对话不问。
- 问法：列 vault 里已有语料的人格名（小烨、林晓丁、玄灵、小沅、玄成先生等），一句带过，不展开推销。
- 用户点了某档：打开对应语料文章学壳再写。人格档案的开口、称呼、收尾优先于默认成稿模具；事实边界、营销黑名单不豁免。
- 用户中途换档：丢掉当前壳，重新对照新档；说「不要人格了」：回默认成稿。
- 不把多位人格混进同一篇；不把人格的口癖泄漏到默认成稿里。
